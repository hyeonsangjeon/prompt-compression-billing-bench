이 문서는 설계 판단의 근거와 상태를 관리한다. 측정값은 [기준선](baseline.md)과 [압축기 정적 측정](compressors.md)에 두고, Project 15 카드에는 상태·다음 행동·문서 링크만 둔다.

## 열린 판단

아래 세 건은 기존 목적 선정 5과제 실험에서 아직 결정하지 않은 기록이다.

| 번호 | 판단할 것 | 현재 근거 | 선택에 따른 다음 행동 | 성격 |
| --- | --- | --- | --- | --- |
| O1 | 판정 불가 기준선 뒤에도 압축 조건을 실행할지 | 5과제 × 20회에서 앞뒤 절반의 범위와 과제별 관측값 집합이 달라 `stop_inconclusive` | 실행하지 않으면 기준선 설계를 다시 본다. 실행하려면 판정 불가 기준선으로 무엇을 비교할지 새 규칙을 먼저 고정한다 | 열린 설계 판단 |
| O2 | 실행한다면 도구별 20회를 유지할지 10회로 줄일지 | 기존 계약은 모든 압축 조건이 기준선의 완전한 반복 수와 같아야 함. 기준선은 20회 | 20회는 기존 반복 수를 지키지만 기준선 판정 문제를 해결하지 않는다. 10회는 결과를 보기 전이라도 계약과 실행 SHA를 바꾸는 일이다 | 열린 설계 판단 |
| O3 | 현재 5과제를 탐색 결과로만 둘지 과제를 넓힐지 | 과제별 기준선 통과가 1/20부터 20/20까지이고, 과거 후보 비중도 0.48%부터 35.29%까지다. squeez 변경 18출현은 2과제에만 있었다 | 현재 표본을 유지하면 일반화 범위를 제한한다. 과제를 넓히면 EDA와 기준선을 새로 수행한다 | 열린 설계 판단 |

O1이 먼저다. 현재 runner는 판정 불가 기준선에서 압축 비교로 자동 진행하지 않는다. 세 판단 중 어느 것도 정적 감소율만으로 정하지 않는다.

## Headroom 기능 범위 정정

**확인 대상:** Headroom `0.36.5` paths-only 정적 측정과 Headroom `0.37.0` 공개 소스. **성격:** 측정 범위 정정·소스 확인·분류 판단.

우리가 확인한 Headroom `0.36.5` paths-only 설정 범위에서는 압축할 메시지나 툴 결과를 종류별로 나누는 위치 제어가 관측되지 않았다. 다만 Headroom `0.37.0`의 `coding` 프로필에는 툴 단위 제외, 파일 읽기 보호, 분석 문맥 보호와 tree-sitter AST 기반 선택 압축 설정이 있다. 사용자 메시지와 시스템 메시지의 압축 여부, 최근 turn 보호, 최소 압축 크기, turn 간 중복 제거와 툴 검색도 따로 설정한다.

따라서 “검토한 여덟 도구 모두 파일 종류나 구간을 자체 구분하지 않는다”는 결론은 사용하지 않는다. 이 저장소가 측정한 값은 `0.36.5` paths-only의 공통 경로 접두어 묶기 0.1976%이며, `0.37.0` `coding` 프로필의 크기·보존·품질 변화는 아직 측정하지 않았다. 자세한 범위는 [압축기 정적 측정](compressors.md#측정-범위와-제품-기능의-구분)에 둔다.

## 별도 발견 — 툴 이름 보호와 bash 파일 읽기

**외부 관측:** 툴 이름만 기준으로 제외하면 같은 파일 읽기가 `Read`가 아니라 `bash`로 실행될 때 보호 경계를 벗어날 수 있다. Headroom의 공개 [Responses API 문제 기록](https://github.com/headroomlabs-ai/headroom/issues/3237)은 `view`와 bash의 `nl`·`sed` 파일 읽기가 손실 압축되고, 에이전트가 정확한 줄을 얻으려고 파일을 다시 읽은 사례를 남긴다. 별도의 외부 관측에서는 bash로 읽은 Python 소스가 39% 압축됐다. 39%는 이 저장소의 측정값이 아니며, 이 요청에 계산 단위와 표본 분모는 포함되지 않았다.

**설계 판단:** 툴 이름 제외만으로 코드 보호를 맡기지 않는다. harness가 툴 이름만 보지 않고 입력이 생성된 경로와 내용을 구분해 코드·지시문·assistant 이력을 보호하고, 허용한 후보 구간만 압축기에 넘기는 요구사항을 유지한다. Headroom `0.37.0`에는 bash 읽기 명령까지 판별하는 `protect_reads`가 있지만, 이 저장소에서는 해당 경로를 아직 실측하지 않았다.

## 다음 실험 후보 — 압축 강도

**결정:** 이번 실험에서는 압축 강도를 별도 축으로 바꾸지 않는다. 현재 해석해야 할 축은 도구, 적용 위치, 기준선 불안정과 과제이며, 강도를 더하면 남은 일정 안에 각 조건의 같은 반복 수를 유지하기 어렵다.

외부 실험에서 전달된 값은 다음과 같다. `f2p`는 외부 실험의 표기를 그대로 옮겼으며, 정의는 전달 자료에 포함되지 않았다. **성격:** 외부 측정 인용이며 이 저장소의 재측정이 아니다.

| 외부 조건 표기 | 입력 token | f2p | 이 저장소의 실행 |
| --- | ---: | ---: | --- |
| `r0.95` | 91,510 | 15.3% | 0회 |
| `r0.9` | 89,013 | 9.2% | 0회 |
| `r0.5` | 60,916 | 9.2% | 0회 |

외부 결과의 과제 수·반복 수·집계 분모는 이 요청에 포함되지 않았다. 이후 결과 문서에서 인용하려면 원 출처의 모델, 도구 버전, 과제와 분모를 함께 확인한다. 현재는 같은 축을 다시 실행하지 않고 Project 15의 다음 실험 후보로 남긴다.

## 문서와 Project의 역할

긴 판단 근거를 이 문서로 옮기고 Project 카드에는 상태, 다음 행동, 이 문서의 절 링크만 두는 방식을 채택한다. 같은 근거의 여러 사본이 카드마다 누적되는 것을 막고, 저장소 커밋 이력에서 판단 변경을 검토할 수 있다.
