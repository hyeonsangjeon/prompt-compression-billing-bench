# 2차 연구: Cache 재사용과 SWE-Lancer 후속 실행

[1차 예비 비교](../01-preliminary-comparison/README.md)가 입력 압축 경로를 기록한 뒤,
별도 실행으로 확인해야 할 두 가지 질문이 남았다. 반복되는
입력을 제공자가 다시 처리하지 않도록 재사용하는 조건을 압축 조건과 함께 비교할 수
있는가? 또, 고정한 소프트웨어 과제 하나를 격리 실행 환경에서 시작해 모델 호출과
채점까지 이어지는 유효한 실행 기록을 만들 수 있는가?

이 폴더는 그 두 후속 실행을 함께 찾을 수 있게 하지만, 둘을 하나의 성능 비교로 묶지는
않는다. Cache 실행은 비교 가능한 요청과 사이클을 분모로 삼고, SWE-Lancer 실행은
고정된 한 과제가 정해진 실행·격리·채점 절차를 끝까지 지켰는지를 본다. 한쪽의 호출
수나 실패 상태로 다른 쪽의 품질을 판단할 수 없다.

## 반복 입력과 압축을 비교할 수 있었나

Cache 실행은 저장된 답을 다시 쓰는지를 본 것이 아니다. 같은 과제의 같은 논리 요청
순번에서 반복되는 입력 처리를 제공자가 재사용할 수 있는지, 그리고 입력을 `squeez`로
압축했을 때 그 결과가 달라지는지를 비교하려 했다. 재사용 `0`, `1`, `2`는 재시도
횟수가 아니라, 같은 압축 조건에서 인정된 일치 선행 요청이 각각 0개, 1개, 2개인
계획된 순서다.

실제 실행에서는 `none`·재사용 `0` 실행 묶음이 끝난 뒤, `none`·재사용 `1`의
`cancel-async-tasks`가 세 번째 요청에 도달했다. 앞선 실행에는 같은 과제의 요청이 두
개뿐이어서 세 번째 요청을 짝지을 수 없었다. 검증기는 그 요청을 제공자에게 보내기
전에 멈췄고, 시도한 첫 사이클은 무효로 남았다. 성공한 제공자 응답은 `18`회였지만
유효한 비교 사이클은 `0`개다. 두 값은 서로 다른 단위를 세므로 모순이 아니다.

따라서 이 기록은 Cache 효과, 미스율, 절감액, 재사용 수준 차이 또는 압축 효과를
계산하지 않는다. [한국어 Cache 요약](cache-reuse/README.md)은 중단 순서와 분모를
설명하고, [영어 전체 Cache 보고서](../../../docs_en/experiment/02-follow-up/cache-reuse/execution-20260923.md)는
측정 조건, 비용 계산, 증거 해시와 공개 인용 경계를 보존한다.

## 고정 소프트웨어 과제가 실행과 채점까지 갔나

SWE-Lancer 실행은 후보 `28565_1001` 하나를 고정하고, 과제 환경을 준비한 뒤 해법
실행기와 모델·도구를 거쳐 채점 결과를 남기는 한 번의 절차를 만들려 했다. 그러나
계획한 실행은 `1`회였는데 실행기가 남긴 별도 출력 묶음이 `2`개 관측됐다. 두 묶음은
모두 격리 실행 환경이 시작되는 동안 시간 초과로 끝났고, 제공자·모델·API·도구·채점기
호출까지 가지 못했다.

초기 제공자 전송 전 검증은 `27/29`로 `task.row`와 `image.config`가 실패했다. 담당자가
통제할 수 있는 입력을 바로잡은 뒤에는 `31/31`이었지만, 그 결과가 앞선 실패나 두 번째
출력 묶음을 지우지는 않는다. 설정은 `disable_internet=true`였는데 보호 절차가 적용된
시작에서는 `allow_internet=true`도 관측됐다. 이 기록의 유효 프로토콜 실행 기록은
`0`개다.

두 `correct=False` 행은 시작 오류를 남긴 자리일 뿐 채점된 오답이 아니다. 모델 품질,
통과율, 순위, 안정성, 대표 비용은 `not_measured`이거나 판정 대상이 아니다.
[한국어 SWE-Lancer 요약](swe-lancer/README.md)은 모델 호출 전에 끊긴 절차를 설명하고,
[영어 전체 SWE-Lancer 보고서](../../../docs_en/experiment/02-follow-up/swe-lancer/fixed-trace-20260923.md)는
고정 조건과 두 실행 결과 묶음의 증거를 보존한다.

## 숫자 0과 상태값을 읽는 법

위의 `0`은 각각 유효 비교 사이클과 유효 프로토콜 실행 기록의 관측 개수다. 문서 안의
모든 `0`이 같은 종류의 측정값은 아니다. 재시도 `0`은 설정값이고, SWE 실행의 API
계산 비용 `USD 0.000000`은 제공자 호출이 없었던 사용량에서 계산한 값이다.
`unknown`, `not_applicable`, `not_measured`, `not_run`은 알 수 없음, 적용 대상 아님,
측정하지 않음, 실행하지 않음을 각각 뜻한다. 이 상태들을 숫자 0이나 성공으로 바꾸어
읽지 않는다.

## 역사 기록과의 경계

- `SWE-Lancer third-benchmark candidate`는 먼저 작성된 후보 검토의 역사적 표현이다.
  새 `03-` 실험 번호를 뜻하지 않으며, 이후의 프로토콜 무효 실행 결과도 아니다.
- EDA round 1과 round 2는 1차 자료를 분류하고 검토한 단계다. 이 폴더의 두 후속
  실행과 같은 실험 번호로 다시 분류하지 않는다.
- 1차 실험 문서, 동결된 영어 snapshot, 복원된 한국어 원문, 기존 그림과 원시 측정
  계보는 제자리에 보존된다.

영어 현재 문서 입구는 [Follow-up study](../../../docs_en/experiment/02-follow-up/README.md)다.
